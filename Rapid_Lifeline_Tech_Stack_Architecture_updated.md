On booking commit, the booking service records booking.confirmed and independently enqueues idempotent dispatch.search_started and hospital.alerted work. Driver matching proceeds without waiting for any hospital response. Each pending hospital alert has independent 10 s reminder/operations-alert and 20 s timeout jobs. Jobs use conditional state transitions and idempotency keys so delayed or duplicate responses cannot turn a declined or timed_out alert into acceptance. At 10 s, send an urgent reminder to the hospital and alert operations. At 20 s, mark timed_out, notify operations, record hospital.timed_out and hospital.alternative_search_started in trip_events and audit_logs, and immediately search the next suitable hospital, excluding hospitals already declined or timed out. A decline starts the same alternative search. A redirect or alternative emits hospital.destination_change_proposed; only hospital.destination_change_confirmed from the assigned driver applies it and permits route recomputation. Rejection emits hospital.destination_change_rejected and alerts operations; no candidate or unrecoverable notification failure moves coordination to needs_ops_resolution. Dispatch continues independently in every hospital-coordination failure case. Queue/notification retries are independent; alert operations on exhausted retries. Never infer acceptance from silence.

The shared event vocabulary is booking.confirmed, dispatch.search_started, dispatch.assigned, dispatch.no_driver, hospital.alerted, hospital.reminder_sent, hospital.accepted, hospital.declined, hospital.redirected, hospital.timed_out, hospital.alternative_search_started, hospital.alternative_found, hospital.destination_change_proposed, hospital.destination_change_confirmed, hospital.destination_change_rejected and hospital.needs_ops_resolution. Persist state-changing events in trip_events and operational/audit actions in append-only audit_logs.

Conventions (follow exactly)
• TypeScript strict: true. No any without a comment.
• API paths are /v1/..., JSON, camelCase fields, ISO 8601 UTC timestamps, money in integer paise (₹1 = 100 paise).
• IDs are UUID v7 stored as uuid. Coordinates are lat, lng as numbers with WGS84.
• Database tables and columns use snake_case; Prisma maps to camelCase.
• All user-facing strings live in packages/shared/i18n/en.json and kn.json; no hard-coded text in components.
• Every API input is validated with a zod schema from packages/shared; invalid input returns 422 with {code, message, fields}.
• Error shape: { "error": { "code": "BOOKING_NOT_FOUND", "message": "..." } } with the right HTTP status.
• Feature flags are rows in table feature_flags, read once per request.
• Commit style: Conventional Commits. One pull request per phase task; CI must be green to merge.

6. Realtime and location pipeline
Location flow
1. Driver app sends a point every 3 s while a trip is active (every 15 s when online and idle) over Socket.IO event loc: {lat,lng,speedKmh,heading,recordedAt}.
2. API updates Redis: GEOADD drv:geo:<category>, hash trip:live:<tripId>, heartbeat drv:hb:<driverId> with TTL 15 s.
3. API publishes trip:<tripId> on Redis pub/sub. Rider socket, hospital socket and every SSE stream for that trip receive location within 1 s.
4. Every 5th point is persisted to trip_locations by the worker (batch insert).
5. The routing module compares each point to the active route polyline (see section 7); a deviation triggers re-route.
6. Offline: the driver app queues up to 500 points on device, flags them buffered, and sends them with /driver/trips/:id/location-batch on reconnect. Buffered points are stored but never shown as live.

7. Core algorithms
Dispatch
1. Candidate set: GEOSEARCH drv:geo:<category> within radius R (3, then 5, then 8 km), drivers with a live heartbeat and is_online and not on a trip.
2. Take the 5 nearest by straight line; compute road ETA with Google computeRouteMatrix (traffic-aware) from each to the pickup.
3. Order by ETA ascending; offer to the first. Offer = push plus socket offer.new; 20 s timer in BullMQ.
4. On decline or timeout, offer to the next; after 5 offers or all candidates exhausted, widen R; after R = 8 km is exhausted, set no_driver.
5. At 30 s without match, offer the rider an upgrade (next higher category at the same fare) via trip.state payload upgrade_offer. Dispatch timers must be coordinated: the 30 s upgrade prompt may be shown while driver offers continue only if the rider explicitly approves the upgrade; otherwise the original category search continues. Use an atomic booking/category update to prevent duplicate active offers across categories.
6. On accept: set state assigned, create tracking link, SMS trusted contacts, compute the to_pickup route.
Hospital ranking
Score from 0 to 100, higher is better. Exclude hospitals with er_open = false (shown greyed, not ranked).
score = 45 × etaScore + 25 × specialtyFit + 20 × capacityScore + 10 × verifiedScore
Component
Definition
etaScore
1 − min(etaMinutes, 40) / 40, ETA from pickup by Google Routes matrix
specialtyFit
1 if the required specialty is in specialties, 0.5 if no specialty required, 0 if required and missing
capacityScore
1 if capacity note updated within 30 min and not marked full, 0.5 if no data or stale, 0 if marked full
verifiedScore
1 if is_verified, else 0
Return the top 3 by score with the components so the UI can explain Why this hospital. The nearest 15 hospitals by straight-line distance are scored per request; results are cached 30 s per pickup cell.
Fare
estimateKm = pickupToHospitalRoadKm; estimate = base + max(0, estimateKm − 5) × perKm; if the booking time is between 22:00 and 06:00 IST multiply by 1.20; range = [estimate, estimate × 1.15], rounded to the nearest ₹10. Final: same formula on actual distance, plus max(0, waitMin − 10) × waitPerMin, capped at 1.25 × range.max unless the hospital changed. All money in integer paise.
Routing and re-route
• Route requests: Google computeRoutes with travelMode DRIVE, routingPreference TRAFFIC_AWARE_OPTIMAL, polylineQuality HIGH_QUALITY, language en or kn.
• Deviation: three consecutive location points more than 80 m from the polyline, or a trip.alert road-closure flag intersecting the remaining route. Compute new route, store as routes.version + 1, push route.new to the driver and trip.reroute plus new ETA to rider, family and hospital. Target: under 5 s end to end.
• Faster-route check: every 60 s on an active leg, request a fresh route; if it is at least 120 s faster than the remaining current route, switch and notify.
• Large vehicles: if vehicles.is_large, request alternatives (computeAlternativeRoutes true) and choose the fastest route that does not intersect any polygon in avoid_zones. If no valid route exists, do not silently use a prohibited route: alert the driver and operations, retain the last safe route only if it remains valid, and require a safe manual resolution.
• Leg switch: on picked_up, compute the to_hospital route immediately.
• Hospital destination: hospital acceptance/decline/timeout is a separate coordination workflow and never gates dispatch assignment. On a confirmed driver destination-change event only, update the active hospital and recompute the route; a proposed destination is never applied before driver confirmation.
